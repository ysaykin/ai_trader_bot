# Architectural Decisions

## ADR-01: 5-Pillar Self-Improving Neural Strategy Architecture (2026-10-26)
- **Context**: Running a single Iron Condor strategy provides only one observation per trading day and uses static entry/exit thresholds that fail when market regimes shift intraday.
- **Decision**:
  1. **Strategy Pipeline**: Run 20 concurrent parameterized Iron Condor variants (`IC_V01`..`IC_V20`) backed by a shared `MarketDataHub` cache and isolated per-strategy leg accounting.
  2. **Trading & Evaluation Pipeline**: Expand strategy execution from binary entry/exit to support `ADD_POSITION`, `TRIM_POSITION`, `ADJUST_PROFIT_TARGET`, and `FLATTEN_NOW`, evaluated via Counterfactual Regret and MFE/MAE capture efficiency.
  3. **Logging Pipeline**: Record 5-minute intraday State-Action-Reward trajectories (`logs/trajectories.jsonl`) capturing market regime features and cross-strategy stress across all 20 variants.
  4. **Learning Pipeline**: Train a Multi-Head Neural Policy Network (`ml/policy_net.py`) that maps market dynamics + 20-grid signals to position scaling, dynamic profit-taking, and strategy selection.
  5. **Self-Improving Bot Loop**: Retrain a Challenger model daily after market close using Purged Walk-Forward CV and require out-of-sample Shadow Mode outperformance before promoting Challenger to Champion, while keeping `RSK-01` ($5k cap) and `RSK-02` (30%->5% sliding scale) as an immutable risk boundary.

## ADR-02: Dependency-Free Recurrent Multi-Head Policy Network (2026-10-26)
- **Context**: Live trading and dashboard containers (`lumibot-bot` and `lumibot-dashboard`) require deterministic, low-latency 5-minute policy evaluation without coupling live order execution to heavyweight deep-learning runtimes or GPU dependencies.
- **Decision**:
  1. **Pure-Python Inference Core (`ml/policy_net.py`)**: Implemented `MultiHeadPolicyNetwork` using immutable `tuple` vectors/matrices, seeded Glorot/Xavier initialization, and strict finiteness and shape checks on all inputs and weights.
  2. **Shared Temporal Regime Encoder**: Processes `[batch][time][feature]` sequences through a `tanh` recurrent hidden state (`regime_size=32` default) to produce an order-sensitive latent regime embedding.
  3. **Three Specialized Policy Heads**:
     - **Position Scaling Head**: Softmax probabilities across `ADD_POSITION`, `HOLD`, `TRIM_POSITION`, and `FLATTEN_NOW`.
     - **Dynamic Profit-Target Head**: Numerically stable sigmoid scaled to `[0.15, 0.80]` (`MIN_PROFIT_TARGET`..`MAX_PROFIT_TARGET`).
     - **Contextual Strategy Selector Head**: Softmax probabilities across the 20 incubator variants (`strategy_count=20`).
  4. **Decoupled Weight Serialization**: Added `state_dict()` and validated `load_state_dict()` hooks so offline training (`ml/train.py`, `ml/continual_learner.py`) can optimize parameters out-of-band and load plain numeric checkpoints into live inference.
  5. **Isolated Test Discovery**: Scoped `pytest` `testpaths = ["tests"]` in `pyproject.toml` so automated verification runs deterministic offline unit and regression suites cleanly.
- **Trade-offs**: Pure-Python matrix arithmetic avoids multi-gigabyte ML dependencies and guarantees fast single-sequence inference at 5-minute cadence, while batch gradient optimization is deferred to the offline training pipeline (`ml/train.py`).

## ADR-03: Offline BPTT Policy Trainer, Live Inference Adapter & Transactional Position Ledger (2026-10-26)
- **Context**: Enabling end-to-end neural policy execution required: (1) training `MultiHeadPolicyNetwork` on variable-length trajectory sequences across multi-head objectives (action, dynamic profit target, strategy selector); (2) feeding live market data into the recurrent policy with robust feature normalization, sequence buffering, and default imputation; (3) strict rejection of non-finite or boolean values during state serialization; and (4) transactional position tracking to prevent cross-strategy quote corruption, premature expiration clearances, and unverified fill assumptions.
- **Decision**:
  1. **Offline Training Loop (`ml/train.py`)**: Implemented `train_policy` supporting joint loss optimization (cross-entropy for action head, MSE for dynamic profit target, cross-entropy for strategy selector) with Backpropagation Through Time (BPTT) unrolling across variable-length sequence batches, analytical parameter gradients, and L2 gradient clipping.
  2. **Live Adapter Bridge (`ml/inference.py`)**: Built `LivePolicyController` to maintain an in-memory sliding sequence window, apply robust z-score / min-max normalization, impute missing market features with neutral defaults, and output deterministic policy decisions.
  3. **Defensive Model State Serialization (`ml/policy_net.py`)**: Updated `load_state_dict` to accept JSON-compatible list/tuple representations of numeric vectors and matrices, converting them to immutable tuples while strictly rejecting boolean values, strings, non-finite values (NaN/inf), and invalid tensor dimensions.
  4. **Pure Option Math (`strategies/iron_condor_math.py`)**: Implemented formal signed basket valuation (`signed_basket_value`), true credit strategy P&L (`credit_strategy_pnl`), and strike selection (`select_short_strikes`), eliminating sign ambiguities in bid/ask credit evaluation.
  5. **Transactional SQLite Position Ledger (`strategies/position_ledger.py`)**: Replaced loose in-memory order tracking with a durable SQLite-backed ledger separating order submissions from broker fills, scaling opening credits proportionally across ADD/TRIM/CLOSE cycles, reserving full wing risk pre-fill, and preventing premature contract clearance before actual expiration passage.
  6. **Canonical Configuration Precedence**: Standardized boolean parsing and canonical `TRADIER_PAPER` precedence (`TRADIER_PAPER` -> `TRADIER_IS_PAPER` -> `TRADIER_SANDBOX`) across bot entrypoints and dashboard management.
- **Trade-offs**: Retaining pure-Python analytical gradients avoids multi-gigabyte PyTorch/TensorFlow dependencies in live trading containers while ensuring 100% reproducible, unit-tested execution across both training and live inference.

## ADR-04: Durable Tradier Multileg Parent/Child Reconciliation, Multi-Day Rollover & Fault-Tolerant Execution (2026-10-26)
- **Context**: Executing 4-leg Iron Condors on Tradier Sandbox/Live revealed critical operational edge cases: (1) Tradier generates separate parent order IDs and child leg order IDs, making naive order matching fail on fill callbacks; (2) bot restarts or market session rollovers risked dropping active positions or prematurely clearing unexpired packages; (3) closing illiquid option legs at market can suffer severe spread slippage; (4) transient broker quote dropouts caused false position liquidations; and (5) partial fills, scale-ins, trims, and exchange fees were not tracked with transaction-level aggregate-cash precision.
- **Decision**:
  1. **Parent/Child Order Mapping & Schema Migrations (`strategies/position_ledger.py`)**: Enhanced SQLite ledger schema with automatic migrations (`order_children`, `terminal_fill` journaling) to durably link Tradier multileg parent IDs with child leg execution IDs, attributing signed quantities, fill prices, and opening credits proportionally.
  2. **Multi-Day Ledger Rollover & Defensive State Preservation**: Positions persist indefinitely across session rollovers and reboots. If broker market data or option chains are temporarily incomplete, positions are retained safely without triggering accidental re-entries or unmanaged orphan positions.
  3. **Order Close Repricing Pipeline (`strategies/iron_condor.py`)**: Close orders initiate as limit orders and reprice incrementally across configurable intervals (`IC_CLOSE_REPRICE_SECONDS`, `IC_CLOSE_MAX_REPRICES`, `IC_CLOSE_PRICE_STEP`), with market order fallback disabled by default (`IC_CLOSE_ALLOW_MARKET=false`).
  4. **Aggregate-Cash P&L & Fee Accounting (`strategies/iron_condor.py`, `dashboard/trade_logger.py`, `trade_logger.py`)**: Integrated explicit contract fee tracking (`OPTION_FEE_PER_CONTRACT`), recording true transaction cash flow and realized net P&L for base trades, scale-ins (`ADD`), trims (`TRIM`), and expirations.
  5. **Process Crash Recovery & Container Policy (`main.py`, `docker-compose.yml`)**: Set Docker service restart policy to `restart: unless-stopped` and added top-level supervisor loop in `main.py` with exponential backoff (`PROCESS_RESTART_BACKOFF_SECONDS=15`), allowing seamless container recovery from SQLite state.
  6. **Opt-in Paper Sandbox Verification Harness (`tests/test_tradier_sandbox.py`)**: Built an opt-in live test suite guarded by `RUN_TRADIER_SANDBOX_WRITE_TEST=1` requiring valid test symbols and API credentials, testing real HTTP submission, status querying, and cancellation without accidental execution in offline environments.
- **Trade-offs**: Adds SQLite writes during order lifecycle events, but provides crash-proof durability and eliminates phantom fills or unmanaged orphan positions. Retaining positions during quote outages prioritizes capital safety over aggressive liquidation.

## ADR-05: Tradier Credential Hardening, Defensive Credit Baseline Recovery & Jev-Bot Lifecycle (2026-10-27)
- **Context**: Operational audits and regression testing identified edge cases: (1) Tradier credentials with leading/trailing whitespace or template placeholders (`your_*`) could cause opaque runtime errors; (2) when broker fill marks are delayed, zero, or missing at position inception, Iron Condor positions risked being abandoned or missing profit-take/stop-loss management; (3) position ledger cash flows excluded partially filled packages (`state='partial'`), locking active positions from exit cash calculations; (4) legacy callers and framework hooks expected `on_trading_iteration_count` on `SPXIronCondor`; and (5) the standalone `jev-bot` runner lacked `.env` auto-loading, structured CLI execution controls (`--once`, `--iterations`), and clean shutdown handling.
- **Decision**:
  1. **Strict Credential Validation & Placeholder Rejection (`main.py`, `tests/test_regressions.py`)**: Sanitized `TRADIER_ACCESS_TOKEN` / `TRADIER_API_KEY` and `TRADIER_ACCOUNT_NUMBER` / `TRADIER_ACCOUNT` by trimming whitespace and explicitly rejecting default template placeholders (`your_*`).
  2. **Defensive Credit Recovery & Unmanaged Contract Retention (`strategies/iron_condor.py`)**: When filled credit cash is unavailable, `_manage_position` now recovers the credit baseline from the submitted package limit price recorded in the SQLite ledger. Open contracts are strictly retained and never abandoned even if fill marks are temporarily unavailable.
  3. **Partial-Fill Cash Flow Inclusion (`strategies/position_ledger.py`)**: Updated `active_opening_cash()` SQL filter to include `state IN ('open', 'partial')`, accurately accumulating cash flow for partial fills during exit evaluation.
  4. **Iteration Telemetry Compatibility (`strategies/iron_condor.py`)**: Added `on_trading_iteration_count` getter and setter to `SPXIronCondor` mapped to `_iteration_count`.
  5. **Jev-Bot Lifecycle, Dotenv Auto-Loading & CLI Options (`jev_bot/config.py`, `jev_bot/main.py`)**: Added optional `python-dotenv` support with fallback, CLI flags for single-shot (`--once`) and bounded iterations (`--iterations`), and graceful `KeyboardInterrupt` stopping.
- **Trade-offs**: Fallback credit calculation using limit price approximates entry credit until exact marks settle, preventing premature contract abandonment or frozen position states while preserving capital safety.

## ADR-06: Local Package Import Hygiene, Fatal Configuration Exit Guard & Resilient Close-Order Recovery (2026-10-27)
- **Context**: Operational audits and multi-package testing identified several environment and lifecycle stability issues:
  1. An untracked legacy `./lumibot/` mock directory in the repository root shadowed the installed upstream `lumibot` distribution during local (non-Docker) Python invocations.
  2. Unrecoverable configuration errors (e.g. invalid broker type, missing or template credentials, non-numeric parameters) previously raised generic `RuntimeError`s caught by the supervisor loop in `main.py`, causing continuous restart loops instead of stopping.
  3. Close order management in `SPXIronCondor` needed protection against orders that never reached the broker or failed submission, and required a positive marketable debit floor ($0.01) when closing contracts whose mid-price reached 0.00 or negative due to decay.
  4. The standalone `jev-bot` required setuptools package discovery in `pyproject.toml`, finite numeric configuration validation (`math.isfinite`), and standard exit code 2 on invalid settings.
  5. Test environments lacking optional UI dependencies (`reflex`) failed test discovery in `test_reflex_dashboard.py`.
- **Decision**:
  1. **Namespace De-shadowing & Import Hygiene (`.gitignore`, `tests/test_import_hygiene.py`)**: Relocated the untracked `./lumibot/` directory to `.legacy/mock_ui_lumibot_shim/`, added `/.legacy/` to `.gitignore`, and created `tests/test_import_hygiene.py` to assert that no local directory shadows upstream `lumibot` and that `lumibot` resolves strictly from the installed distribution.
  2. **Fatal `ConfigurationError` Separation (`main.py`, `tests/test_regressions.py`)**: Introduced `ConfigurationError(RuntimeError)` for unrecoverable setup issues (invalid brokers, credentials, parameters). Caught at the top-level `run()` entrypoint to log a critical error and terminate immediately without restarting.
  3. **Resilient Close-Order Recovery & Repricing Floor (`strategies/iron_condor.py`, `tests/test_regressions.py`, `tests/test_strike_selection_and_pnl.py`)**: Added check for close packages that never reached the broker or failed submission; after timeout (`max(_close_reprice_seconds, 60.0)`), they are marked `failed` in `PositionLedger` and safely rescheduled. In `_package_price`, ensured closing debit orders never return `< 0.01` even when mid-price decay reaches 0.0. Added UTC timezone normalization (`_as_aware_utc`) and recursive tag matching (`_find_order_by_tag`).
  4. **Jev-Bot Hardening (`jev_bot/config.py`, `jev_bot/main.py`, `pyproject.toml`, `tests/test_entrypoint.py`, `tests/test_structure.py`)**: Added `math.isfinite` validation to prevent `NaN`/`inf` parameters, caught configuration `ValueError`s to log and exit with code 2, and added `[tool.setuptools.packages.find]` for package discovery.
  5. **Resilient Test Discovery (`tests/test_reflex_dashboard.py`)**: Added `pytest.importorskip("reflex")` to avoid test crashes when optional UI dependencies are not installed.
- **Trade-offs**: Non-restarting fatal exit terminates the process on bad configuration rather than entering a backoff loop, requiring valid environment credentials before starting the trading loop. Relocating legacy prototypes ensures clean upstream package imports for developers and CLI tools.

## ADR-07: StrategyBro 90 DTE Dynamic Iron Condor vs Vertical Spread (2026-10-28)
- **Context**: To mimic StrategyBro's 90 DTE dynamic playbook, the system needed a variant capable of dynamically selecting between an Iron Condor and a single-side Vertical spread based on standard deviation (Z-score) of the underlying asset from its historical mean, with percentage OTM strike selection, a 30 DTE roll trigger, and an entry quality filter.
- **Decision**:
  1. **Dynamic Structure Resolution (`strategies/iron_condor_math.py`, `strategies/iron_condor.py`)**: Implemented `calculate_zscore`, `evaluate_strategybro_entry_quality`, and `resolve_strategybro_structure`:
     - `Abs SD <= 0.60` $\to$ `iron_condor`
     - `Abs SD > 0.60 & positive` $\to$ `bear_call` (Sell Call Vertical)
     - `Abs SD > 0.60 & negative` $\to$ `bull_put` (Sell Put Vertical)
     - `Abs SD > 1.50` $\to$ Avoid zone (entry skipped)
  2. **Percentage-OTM Strike Selection (`strategies/iron_condor_math.py`, `strategies/iron_condor.py`)**: Added `select_short_strikes_otm_pct` selecting short put and call strikes at configurable target OTM distances (default 7% OTM), verifying outer wing availability.
  3. **30 DTE Management & Roll Trigger (`strategies/iron_condor.py`)**: Added `_days_to_expiration` calculation; `_manage_position` triggers an early exit with `exit_reason="ROLL_DTE"` when remaining DTE reaches $\le 30$ (or upon reaching 50% profit target).
  4. **Incubator Integration (`strategies/incubator.py`)**: Added `get_strategybro_spec()` registered into `get_incubator_specs()` as `IC_V25_90DTE_STRATEGYBRO_DYNAMIC` (`STRATEGYBRO_ENABLED=true`), fully isolated with shared `MarketDataHub`.
- **Trade-offs**: Calculating Z-score uses historical daily closes with a 0.0 fallback (Iron Condor) if historical data is unavailable, ensuring safe execution even during broker data initialization.

## ADR-08: Intraday Execution Schedule Expansion through 3:31 PM ET Every 30 Minutes (2026-10-28)
- **Context**: Limiting strategy entries to static morning windows (09:45, 10:00, 10:15, 10:30) restricted data collection, trading observations, and opportunities to enter after morning positions closed at profit targets or stop losses.
- **Decision**:
  1. **Expanded 30-Minute Execution Schedule (`strategies/iron_condor.py`, `strategies/incubator.py`)**: Expanded default execution run times across all strategies to 15 slots spanning the trading day: `09:45, 10:00, 10:15, 10:30, 11:00, 11:30, 12:00, 12:30, 13:00, 13:30, 14:00, 14:30, 15:00, 15:30, 15:31`.
  2. **Strict Hard Cutoff at 3:31 PM ET (`_is_entry_window`)**: Enforced a hard cutoff at 15:31 (`time(15, 31)`) so no new positions are entered after 3:31 PM, preventing pin risk or entering expiring contracts right before the 16:00 close.
  3. **Pure Neural Active Window Expansion**: Expanded dynamic neural trading window from `10:00 - 15:30` to `09:45 - 15:31`.
  4. **Grid-Wide Strategy Synchronization (`strategies/incubator.py`)**: Applied the expanded schedule across all 20 benchmark incubator variants (`IC_V01`..`IC_V20`), testing variant (`IC_V21`), pure neural strategy (`IC_V22`), standalone verticals (`IC_V23`, `IC_V24`), StrategyBro dynamic (`IC_V25`), and A/B lab strategies.
  5. **Dashboard Presentation Formatting (`reflex_dashboard/reflex_dashboard/data/adapters.py`)**: Added `format_entry_schedule` helper rendering compact summaries (`09:45 - 15:31 ET (Every 30m)`) in table views with full timestamp lists preserved in `entry_time_full`.
- **Trade-offs**: Staggered 30-minute intervals ensure continuous opportunity evaluation throughout the day whenever positions become flat, while the 15:31 cutoff preserves risk boundaries before 0DTE settlement.

## ADR-09: Expiration-Specific Strike Filtering, Per-Strategy Risk Isolation & Immediate Trade Inception Visibility (2026-10-28)
- **Context**: Operational monitoring revealed three live execution and reporting impediments:
  1. Multi-day variants (7DTE, 14DTE, 21DTE, 30DTE, 90DTE) failed order submission because `_find_short_strikes` extracted strikes across all 44 expirations unioned by Tradier, selecting $1-increment strikes that only existed on 0DTE chains and triggering `Invalid symbol` quote errors.
  2. Defined risk limit checks evaluated account-wide open risk against single-strategy parameters, causing active trades in one variant to block entries in unrelated variants.
  3. The Reflex dashboard only counted and rendered closed trades, leaving open positions invisible in the primary trade stream and reporting 0 trades for newly active strategies.
- **Decision**:
  1. **Expiration-Specific Strike Filtering (`strategies/iron_condor.py`)**: Updated `_fetch_strikes(chains, expiry=expiry)` to filter strikes strictly from `chains["Chains"]["CALL"][exp_str]` and `["PUT"][exp_str]`, guaranteeing only quoteable strikes are selected.
  2. **Per-Strategy Risk Cap Isolation (`strategies/iron_condor.py`, `.env`)**: Scoped `portfolio_defined_risk(self._strategy_id())` to enforce risk limits independently per strategy ($15,000 default) with an overarching $100,000 global portfolio cap.
  3. **Opposing-Leg Conflict Prevention (`strategies/iron_condor.py`)**: Added pre-submission cross-check against `PositionLedger.all_owned_quantities()` to reject packages containing legs that oppose existing open positions, preventing broker "Buy to Cover" rejections.
  4. **Immediate Trade Inception Visibility (`reflex_dashboard/reflex_dashboard/data/adapters.py`)**: Unified trade counts as `total_trades = open + closed`, formatted open trades with real-time tokens (`status="OPEN"`, cyan badges), and prepended them to `visible_trades_50 = (open_all + closed_all)[:50]`.
  5. **Fee-Adjusted Net Win Rate (`reflex_dashboard/reflex_dashboard/data/adapters.py`)**: Classified trades with negative net P&L after fees as losses, maintaining accounting integrity.
- **Trade-offs**: Expiration-specific filtering adds dictionary key lookups across chains, but eliminates invalid symbol rejections and ensures reliable execution across all maturities.

## ADR-10: Confirmed Opening Credit Enforcement, Roll/DTE Exit Precedence & Tradier Log Redaction (2026-10-30)
- **Context**: Operational audits and regression reviews identified two safety vulnerabilities in position lifecycle management and broker connectivity:
  1. When opening credit was delayed or unconfirmed by broker fill events, `SPXIronCondor._manage_position` attempted fallback valuation using the submitted package limit price. This manufactured an unverified entry credit baseline that could trigger premature profit-taking or incorrect stop-loss actions when actual fill prices differed from the limit price.
  2. The position lifecycle checked opening credit availability before evaluating roll/DTE exit targets. If opening credit marks were delayed or unavailable, the strategy bypassed `roll_dte` checks, leaving aging positions unmanaged past their roll threshold.
  3. Tradier connection logs printed `ACCOUNT_NUMBER` in plain text during initialization, leaking sensitive identifiers in runtime logs.
  4. Tradier polling cadence was hardcoded without configurability across paper and live environments.
- **Decision**:
  1. **Strict Confirmed Opening Credit Enforcement (`strategies/iron_condor.py`)**: Removed limit price credit recovery fallback. Required finite, positive confirmed cash (`_entry_credit_cash`). If opening credit is unconfirmed, the strategy publishes `VALUATION_UNAVAILABLE` and returns safely while strictly retaining open contracts (never resetting `_position_open = False` or clearing `_owned_legs`).
  2. **Roll/DTE Exit Precedence Ahead of Valuation (`strategies/iron_condor.py`)**: Reordered `_manage_position` to evaluate `roll_dte` against `_days_to_expiration()` before checking opening credit availability or calculating option marks. When `remaining_dte <= roll_dte`, immediately triggers `_close_all_options(exit_reason="ROLL_DTE")`.
  3. **Tradier Connection Log Sanitization (`main.py`)**: Redacted account numbers from startup logs, logging only paper mode status and polling interval (`Connecting to Tradier (paper=%s, polling_interval=%.1fs)...`).
  4. **Configurable Polling Interval (`main.py`, `.env.example`)**: Added `TRADIER_POLLING_INTERVAL` parsing with a 1.0s minimum floor, defaulting to 15.0s for paper trading and 5.0s for live trading.
  5. **Jev-Bot Lifecycle and Multi-Entrypoint Verification (`tests/test_config.py`, `tests/test_bot.py`, `tests/test_entrypoint.py`, `tests/test_structure.py`)**: Verified clean lifecycle termination, isolated test environments from local `.env`, and asserted single-step execution across root script, module (`python -m jev_bot`), and installed CLI command.
- **Trade-offs**: Rejecting limit-price fallback prevents phantom P&L triggers but temporarily pauses profit/loss exit checks until fill credit confirms; capital safety is maintained by strict contract retention and subsequent EOD liquidation guards.

## ADR-11: Tradier Host Strategy Tag Routing, Order Tag De-collision & Resilient Closing Package Retention (2026-10-31)
- **Context**: Executing multiple Iron Condor variants concurrently on Tradier with shared host routing exposed two critical order management and reconciliation failure modes:
  1. Sub-strategies (incubator variants) submitting atomic multileg orders needed to route callbacks through the registered host strategy's tag while maintaining isolated package IDs and ledger ownership. However, if multiple orders share a strategy-level tag, `_find_order_by_tag` could match the wrong order, corrupting order-to-package bindings.
  2. When closing orders timed out or were not immediately visible in broker query responses (e.g. during query lag or network latency), `_manage_position` previously marked the close package as `failed` and attempted resubmission. In reality, the original closing order might still be live at the broker, risking duplicate closing submissions and conflicting position states.
- **Decision**:
  1. **Normalized Host Strategy Routing Tag (`strategies/iron_condor.py`)**: Added `_broker_routing_tag()` to derive sanitized, alphanumeric tags from the registered host strategy name (`self._host_strategy.name` or `self.name`). Verified non-empty host tags before submission.
  2. **Unique Legacy Tag Resolution & Parent/Child Matching (`strategies/iron_condor.py`)**: Restricted `_find_order_by_tag` to match only unique legacy package tags matching `r"IC_?([0-9a-f]{20})"`. Shared host tags are never used for package identity resolution. Enhanced reconciliation to map parent orders by child IDs (`parents_by_child`) and flag ambiguous orders if multiple parents exist.
  3. **Resilient Closing Order Retention & Recovery Lock (`strategies/iron_condor.py`)**: When an active close package's parent order is not found among broker orders, the strategy sets `self._recovery_lock = True` and exits `_manage_position` safely instead of marking the package failed or resubmitting. Open contracts and ledger ownership are retained until broker reconciliation observes an explicit terminal status (filled, canceled, rejected).
  4. **Offline Contract Tests & Broker Regressions (`tests/test_tradier_order_routing.py`, `tests/test_regressions.py`)**: Added offline contract tests covering host routing tag normalization, multileg order serialization, polling interval configuration, and host callback routing.
- **Trade-offs**: Retaining unresolved close orders under a recovery lock prevents duplicate closing orders during broker communication hiccups, at the cost of pausing further automated action on that package until reconciliation clarifies broker order status.

## ADR-12: Panic Liquidation Flattening, Durable Trading Halt, Dynamic Leg-Count Fees, Terminal Partial-Fill Reconciliation & Multi-Slot Entry Schedules (2026-10-31)
- **Context**: Operational testing and adversarial review uncovered critical gaps across emergency controls, fee calculations, partial-fill order lifecycle, and neural schedule transitions:
  1. `execute_panic_liquidation` in the Reflex dashboard imported a non-existent `BrokerClient` class and called a no-op stub `emergency_flatten_positions()` that only cancelled open orders without closing positions, while falsely reporting liquidation success.
  2. Following a panic liquidation or emergency shutdown, running strategy loops lacked a persistent halt signal, allowing strategies to continue polling and entering new positions on subsequent iterations.
  3. Commission and fee accounting hardcoded 4-leg (or 8-leg roundtrip) multipliers across `SPXIronCondor`, `trade_logger.py`, and `dashboard/trade_logger.py`, overcharging 2-leg vertical spreads by 2x and distorting live `net_pnl` exit triggers.
  4. Inflight order reconciliation only handled terminal states for unfilled packages (`refreshed.state == "submitted"` and zero fills). When partially filled packages were canceled or expired by the broker, they remained trapped in state `"partial"`, deadlocking `_manage_position` and subsequent close submissions. Additionally, cumulative broker fills were incorrectly re-averaged with slice weighting.
  5. Multi-slot comma-separated `entry_time` strings (`"09:45, 10:15, ..."`) raised `ValueError` in `_apply_neural_strategy_switch` because it split on `:` directly, leaving `_entry_times` stale.
- **Decision**:
  1. **Strict Verified Broker Liquidation (`dashboard/broker_client.py`, `reflex_dashboard/reflex_dashboard/state.py`)**: Replaced the mock/stub with `TradierClient.emergency_flatten_positions()`. The routine queries all open orders via paginated `_fetch_all_orders()` and cancels working orders; queries all positions via `_fetch_all_positions()`; submits market orders closing short option legs (`buy_to_close`) before protective long option legs (`sell_to_close`) (and equity `buy_to_cover`/`sell`); polls boundedly until zero working orders and zero positions remain; and surfaces per-symbol errors to dashboard toast notifications.
  2. **Durable SQLite Panic Halt (`strategies/position_ledger.py`, `strategies/iron_condor.py`, `reflex_dashboard/reflex_dashboard/state.py`)**: Added a persistent `system_state` key-value table in `PositionLedger` with `set_panic_halt(True)` and `is_panic_halted()`. Triggered on panic liquidation, and checked by `SPXIronCondor` at the start of `_run_trading_iteration`, `apply_policy_action`, and `_apply_neural_strategy_switch` to halt all new entries and policy adjustments.
  3. **Dynamic Leg-Count Fee Accounting (`strategies/iron_condor.py`, `strategies/iron_condor_math.py`, `trade_logger.py`, `dashboard/trade_logger.py`)**: Added resilient `option_fee_per_contract()` helper handling empty strings, negative numbers, or non-numeric env overrides. Scaled entry, addition, exit, and roundtrip fees dynamically by `len(legs)` or `len(strikes)` (e.g. 2 legs for vertical spreads vs. 4 legs for iron condors). Updated `_record_filled_entry` max risk to scale by filled quantity rather than initial parameter quantity.
  4. **Terminal Partial-Fill Reconciliation & Cumulative Pricing (`strategies/position_ledger.py`, `strategies/iron_condor.py`)**: Added `PositionLedger.resolve_partial_package()`. When broker orders hit terminal states (`canceled`, `rejected`, `expired`, `failed`), partially filled entry/add packages transition to active `"open"` packages, and partial close/trim packages transition to `"canceled"` so new close orders can be submitted cleanly. Updated `PositionLedger.record_fill` to apply cumulative fill prices directly as `weighted_price`. Added deduplication guards in `SPXIronCondor` to prevent duplicate trade journal events.
  5. **Multi-Slot Schedule Parsing in Neural Switches (`strategies/iron_condor.py`)**: Integrated `self.set_run_times()` into `_apply_neural_strategy_switch`, ensuring comma-separated schedules update both `self._entry_times` and `self._entry_time` without runtime errors.
- **Trade-offs**: Closing short legs before long legs during emergency liquidation requires slightly higher sequential execution latency during high-stress market events, but eliminates transient naked short exposure and broker margin violations.

## ADR-13: Close Package Trade-Scoping, Reprice Cooldown Clock Alignment, Exit Reason Preservation, Read-Only Ledger Resilience & Sign-Aware Telemetry Formatting (2026-10-31)
- **Context**: Adversarial review and edge-case testing uncovered execution safety and telemetry defects:
  1. `SPXIronCondor._close_all_options` deadlocked all subsequent close attempts on Trade #2+ because `latest_basket({"close"})` returned the historical closed package from Trade #1 across the entire database without scoping to the current open trade.
  2. Retrying `_close_all_options` or triggering hooks (`before_market_closes`, `on_abrupt_closing`) clobbered pending exit reasons (`STOP_LOSS`, `PROFIT_TARGET`) to `None` or `"MANUAL"`, and erased pending P&L attributes.
  3. Reprice cooldown `(self.get_datetime() - updated).total_seconds() < 60` failed in simulations where strategy time lagged wall-clock time (`updated` stamped with wall-clock `_utc_now()`), producing negative elapsed seconds and permanently suppressing replacements.
  4. `PositionLedger.risk_snapshot` raised unhandled `sqlite3.OperationalError` on uninitialized or 0-byte database files, and `:memory:` failed in `read_only=True` URI mode.
  5. `TrajectoryLogger._strategy_state` used configured `parameters["quantity"]` rather than actual owned legs, omitted quantity when scaling credit cash in `pnl`, hardcoded a $5,000 risk cap, and `can_add` evaluated aggregate risk against per-strategy cap rather than portfolio cap.
  6. Dashboard telemetry displayed fabricated balances, hardcoded sandbox account ID `"VA21359019"`, hardcoded `/app/...` paths, green negative P&L/drawdowns, and outdated $5,000 / 30% risk gauge labels.
- **Decision**:
  1. **Current Trade Scoping for Close Repricing (`strategies/iron_condor.py`)**: In `_close_all_options`, scoped `previous` close packages to `latest_close.created_at >= latest_open.created_at`, ensuring Trade #1's closed status does not block Trade #2's close lifecycle or contaminate reprice counters. Added state attribute reset (`_exit_requested = False`, `_pending_exit_reason = None`, etc.) in `_hydrate_from_ledger()` when positions become flat.
  2. **Exit Reason & Metadata Retention (`strategies/iron_condor.py`)**: Preserved `_pending_exit_reason` (and pending gross/fees/net P&L) across retries when `exit_reason is None`. Passed explicit fallbacks (`getattr(self, "_pending_exit_reason", None) or "EOD_CLOSE"` / `"ABRUPT_CLOSE"`) from EOD and abrupt close hooks. Fixed `_record_filled_exit` to use `self._pending_exit_reason or "MANUAL"`.
  3. **Clock-Source Alignment & Cooldown Protection (`strategies/position_ledger.py`, `strategies/iron_condor.py`)**: Supported explicit `created_at` in `record_submission` and `updated_at` in `record_terminal_status` / `resolve_partial_package` stamped with strategy clock (`self._current_datetime()`). Bounded reprice cooldown check with `0 <= elapsed < self._close_reprice_seconds`, eliminating clock-skew suppression.
  4. **Read-Only Ledger Resilience (`strategies/position_ledger.py`)**: Handled `:memory:` cleanly in `read_only=True` without URI mode, protected `risk_snapshot()` with table existence checks and operational error fallbacks returning empty snapshots safely.
  5. **Trajectory Logger Book Quantity & Portfolio Risk Alignment (`trade_logger.py`, `tests/test_trajectories.py`)**: Derived book quantity from actual owned leg sizes (`actual_quantity = max(leg_quantities)`), scaled credit P&L by `book["quantity"]`, respected configured `max_position_risk`, evaluated `can_add` against `IC_MAX_PORTFOLIO_RISK` ($100k), and unsquared quantity in `test_trajectories.py:88`.
  6. **Telemetry Validity & Sign-Aware Formatting (`reflex_dashboard/`, `dashboard/`)**: Removed hardcoded sandbox account `"VA21359019"` and fabricated empty-state narratives; aligned config form and adapters to `TRADING_BROKER`, `TRADIER_ACCOUNT_NUMBER`, `IC_MAX_POSITION_RISK`, `IC_MAX_PORTFOLIO_RISK`, and `TRADIER_PAPER`; bound per-strategy and portfolio risk limits to dynamic state values; replaced green negative P&L/drawdowns with red (`CRIMSON`); and resolved file paths dynamically relative to `__file__`.
- **Trade-offs**: Scoping close packages to `created_at >= latest_open.created_at` requires checking `latest_open` during close execution, which adds a lightweight query but strictly isolates distinct trade lifecycles across strategy history.

## ADR-14: Emergency Execution Exclusion, Verified Short-First Liquidation & Recovery Boundary (2026-11-01)
- **Context**: Repair work closed the critical race between ordinary strategy submissions and panic liquidation, strengthened broker response validation, and enforced short-option closure before releasing protective longs. The remaining recovery retries are initiated from halted strategy iterations; they do not have an independently managed lifecycle.
- **Decision**:
  1. **Shared Cross-Process Execution Gate (`strategies/position_ledger.py`, `strategies/iron_condor.py`, `reflex_dashboard/reflex_dashboard/state.py`)**: Serialize strategy order submission and dashboard panic liquidation with a filesystem-backed lock keyed to the ledger path. Recheck the durable halt while holding the gate before submitting strategy orders.
  2. **Verified Broker State & Short-First Sequencing (`dashboard/broker_client.py`, `tests/test_emergency_liquidation.py`)**: Treat malformed or incomplete order/position responses as failures. Do not continue to protective-long closes until short positions have been confirmed closed and no working orders remain. Preserve an explicit failure result when the final flat-state verification cannot be established.
  3. **Writable Dashboard Ledger (`docker-compose.yml`)**: Mount the logs directory writable so panic halt state can be persisted by the dashboard container.
  4. **Recovery Lifecycle Limitation**: Keep a managed recovery supervisor with startup/shutdown pending. Current retries run only when strategy iterations execute, so this does not provide recovery independent of strategy scheduling.
- **Trade-offs**: A filesystem lock coordinates processes sharing the same ledger path and filesystem; deployments that do not share that path cannot coordinate through this gate. Short-first verification adds latency but avoids exposing protective longs while shorts may remain open.

## ADR-15: Capital Safety Quote Dropouts, Multi-Expiry Ledger Scoping, Emergency Limit Capping & Dynamic Dashboard Reconciliation (2026-11-01)
- **Context**: Adversarial review and verification revealed execution safety and telemetry edge cases:
  1. Option quote dropouts during live position management caused remaining single legs to be valued as naked options, fabricating catastrophic loss spikes and triggering unwarranted stop-losses.
  2. Emergency fallback pricing was capable of submitting debit limits up to 3x wing width, and quote-less roll exits could liquidate multi-day positions at maximum loss during temporary quote outages.
  3. Tradier quote normalization lacked bounded backoff on rate limits (`429/502/503/504`), failed to enforce CBOE $0.05 tick rounding on index options, and raised exceptions on $0.00-bid protective longs after short leg liquidation.
  4. In multi-expiry portfolios, `PositionLedger.active_opening_cash` and `PositionLedger._refresh_package` operated across all open packages regardless of expiration, zeroing active cash credit or prematurely transitioning unrelated packages to closed.
  5. `reflex_dashboard` trade reconciliation merged events via `dict.update()`, overwriting entry timestamps and entry fees on exit, ignoring addition/adjustment cash flows, and diluting closed-trade win-rate with open trades.
  6. Legacy React dashboard form lacked input `name` attributes, native submit reloaded the page, `#closeBtn` was unwired, and FastAPI mock backend inverted cash/credit calculations.
- **Decision**:
  1. **Wing-Grouped Valuation on Quote Dropouts (`strategies/iron_condor.py`)**: Grouped legs into wings by `(right, expiration)`. If quotes drop out, compute conservative closing debit only when both legs of a wing are quoted or via spot intrinsic when expiring today. Otherwise safely retain open positions with `VALUATION_UNAVAILABLE`.
  2. **Emergency Fallback Price Capping & Roll DTE Quote-Wait (`strategies/iron_condor.py`)**: Capped emergency limit orders strictly at `wing_width` (never `width * 3.0`) and computed debit targets from `min(width, max(credit_target, paired_natural_or_intrinsic, 0.01))`. Restricted quote-less fallback closes strictly to same-day expiration emergencies (`_is_expiring_today()` or reasons `{"EOD_CLOSE", "FLATTEN_NOW"}`), requiring multi-day roll exits to wait for quotes.
  3. **Tradier Exponential Backoff, Tick Rounding & $0.00 Long Liquidation (`dashboard/broker_client.py`)**: Added `_request_with_backoff` with bounded exponential backoff for `429/502/503/504`. Applied CBOE $0.05 tick rounding to index options, and offered $0.00-bid protective longs at minimum tick ($0.05) to avoid verification failures.
  4. **Expiry-Scoped Multi-Package Ledger Cash & Closures (`strategies/position_ledger.py`)**: Scoped package closure checks in `_refresh_package` to the specific `(symbol, expiration)` group(s) of the closed package. Grouped active quantities in `active_opening_cash` by `(symbol, expiration)` to prevent cross-expiry cash distortion. Standardized canonical strike keys (`long_put`, `short_put`, `short_call`, `long_call`) in `_record_filled_entry()`.
  5. **Event-Aware Trade Reconciliation & Dynamic Benchmarks (`reflex_dashboard/data/adapters.py`, `reflex_dashboard/state.py`, `reflex_dashboard/components/benchmark_view.py`)**: Accumulated quantities, credits, fees, and realized adjustment P&L across `ENTRY`, `ADDITION`, `ADJUSTMENT`, and `EXIT` events; preserved entry timestamps and tracked exit timestamps; computed win rate strictly over closed trades; and bound benchmark scorecards to dynamic metrics computed from closed trades.
  6. **Legacy React Form & Mock Backend Accounting (`dashboard/src/App.jsx`, `backend/app.py`, `tests/test_mock_backend.py`)**: Added `name` attributes, prevented form reload on submit, wired `#closeBtn`, corrected cash/equity math in `backend/app.py`, and added test coverage.
- **Trade-offs**: Restricting emergency fallback closes to same-day expirations avoids liquidation at max loss during temporary quote outages, but requires multi-day options to wait for broker quote availability before executing rolls.

## ADR-16: Shared Absolute Ledger Resolution, Bot Image Recovery Packaging, Strict Neural Opt-In & Execution Lock Protection (2026-11-02)
- **Context**: In multi-process and multi-container environments (trading bot and Reflex dashboard), relative SQLite ledger paths (`logs/position_ledger.sqlite3`) resolved to different working directories (`/app` vs `/app/reflex_dashboard`), creating split-brain panic halts and isolated execution locks. Additionally, the trading bot container lacked `dashboard.broker_client` for panic recovery retries, and the policy controller attached automatically to pure-neural strategies even when `ML_POLICY_ENABLED` was false or unset.
- **Decision**:
  1. **Canonical Absolute Ledger Resolution (`strategies/position_ledger.py`, `docker-compose.yml`, `main.py`)**: Added `resolve_ledger_path()` anchoring relative paths to the project root directory. Explicitly injected `POSITION_LEDGER_PATH=${POSITION_LEDGER_PATH:-/app/logs/position_ledger.sqlite3}` into both bot and dashboard services in `docker-compose.yml`. Keyed the cross-process execution lock (`execution.lock`) directly off the resolved ledger directory.
  2. **In-Lock Panic Halt Verification (`strategies/iron_condor.py`)**: Moved the durable panic halt check immediately inside the cross-process execution lock right before order submission to eliminate TOCTOU races between strategy entry orders and panic liquidation.
  3. **Bot Image Recovery Packaging (`Dockerfile`)**: Copied `dashboard/broker_client.py` and `dashboard/presentation.py` into `dashboard/` within the trading bot image to ensure the emergency broker client and its dependencies are present in production without runtime `ModuleNotFoundError`.
  4. **Strict Explicit Neural Opt-In (`main.py`)**: Removed automatic controller attachment when `ML_POLICY_ENABLED` is false or unset. Live policy controllers now attach strictly when `ML_POLICY_ENABLED=true`, and management-only roster strategies are excluded from policy routing and trajectory callbacks.
  5. **Terminal Package Reconciliation Guardrails (`strategies/position_ledger.py`, `strategies/iron_condor.py`)**: Required verified leg execution evidence before completing terminal packages; retained unbalanced packages as partial. Added duck-typing to `LedgerLeg` coercion for cross-module import resilience. Added a reconciliation check prior to closing restarted entries to prevent racing fills from reopening unmanaged exposure.
- **Trade-offs**: Anchoring relative paths to project root requires reliable directory resolution across testing and container environments, but guarantees that all processes operate on the exact same database file and lock.

## ADR-17: Shared Broker Read Caching, Independent Multi-Tranche Positions, Zero/Debit Stop Protection & Resilient Reservation Recovery (2026-11-03)
- **Context**: Operational monitoring and stress-testing under multi-strategy concurrency revealed several architectural friction points:
  1. Multiple strategy instances and active dashboard sessions independently polled Tradier REST endpoints, causing rate limit pressure, 500 RetryError storms, and UI flicker between valid and N/A values.
  2. Single-position tracking prevented strategies from holding multiple independent tranches across intraday schedule slots without contaminating entry basis and exit intent.
  3. Positions restored with zero opening credit or debit were treated as `VALUATION_UNAVAILABLE`, preventing P&L stop exits, while zero-priced closing limit orders were rejected or failed to fill at broker.
  4. Pending entry orders interrupted before broker transmission left durable ledger reservations that blocked subsequent closing orders, while releasing them without evidence risked racing execution fills.
  5. Dashboard risk gauges hardcoded legacy $5,000 / 30% sizing labels and failed to decouple individual variant risk utilization from the global portfolio cap.
- **Decision**:
  1. **Shared Broker Snapshot Store & Coordinated Backoff (`strategies/broker_reads.py`)**: Created `BrokerReads` backed by a shared SQLite snapshot cache (`logs/broker_snapshots.sqlite3`). Routed SDK GET requests and dashboard telemetry through snapshot leases, coalescing concurrent reads across processes. Batched option quotes and applied bounded exponential backoff to HTTP 429/500 responses with sanitized `X-Ratelimit-*` accounting.
  2. **Multi-Tranche Independent Positions (`strategies/position_state.py`, `strategies/position_ledger.py`, `strategies/iron_condor.py`)**: Introduced explicit `position_id` tracking across ledger packages and runtime state, enabling concurrent independent tranches per strategy (e.g. up to 2 positions with 60-minute entry spacing) with isolated credit, basis, defined risk, and exit triggers.
  3. **Zero/Debit Position Valuation & Minimum Tick Close Fallback (`strategies/iron_condor.py`, `tests/test_regressions.py`)**: Preserved negative opening cash (debit) upon ledger hydration; evaluated stop losses for zero/debit positions against max defined loss; and allowed closing orders priced at $0.00 to submit at $0.01 debit to ensure fill viability.
  4. **Durable Submission Markers & Safe Reservation Recovery (`strategies/position_ledger.py`, `strategies/iron_condor.py`)**: Added `submission_started` column to ledger packages. Pending baskets with `submission_started == 0` can be safely cleared as `failed` during closing routines, whereas uncertain baskets (`submission_started != 0`) remain reserved until broker evidence confirms terminal status.
  5. **Decoupled Risk Utilization Telemetry (`reflex_dashboard/components/risk_gauges.py`, `reflex_dashboard/data/adapters.py`)**: Decoupled per-strategy risk ceiling ($15,000 default) from global portfolio cap ($100,000 default), dynamically bound gauge values to live ledger metrics, surfaced broker margin and buying power headroom, and removed legacy hardcoded tier labels.
- **Trade-offs**: Retaining uncertain reservations until broker confirmation requires manual or evidence-based resolution for un-tracked legacy orders, but strictly eliminates the risk of double-submitting or generating naked fills.

## ADR-18: Post-Market Continual Learning Pipeline, Purged Walk-Forward Cross-Validation, Champion/Challenger Promotion Gate & Dynamic Telemetry (2026-11-03)
- **Context**: The multi-head neural policy network (`MultiHeadPolicyNetwork`) had been operating on static weights from October 26, leaving over a week of accumulated intraday trajectory data (`logs/trajectories.jsonl`, 900+ rows) un-utilized. In addition, the Reflex dashboard Neural Policy view displayed hardcoded placeholder values for latent regime, dynamic profit target, contextual selector, and counterfactual regret, giving the impression that neural adaptation had stalled.
- **Decision**:
  1. **Post-Market Continual Learning Engine (`ml/continual_learner.py`)**: Built `ContinualLearner` implementing Pillar 5 (`ML-08`). Ingests trajectories, executes automated post-market relabeling on completed sessions, and orchestrates offline candidate retraining.
  2. **Purged Walk-Forward Cross-Validation (`ml/continual_learner.py`)**: Enforced chronological partitioning of trading sessions into train, purge, and validation holdout folds. Purging the boundary session prevents multi-day autocorrelation leakage.
  3. **Champion vs. Challenger Shadow Gate & Lineage Tracking (`ml/continual_learner.py`, `logs/models/model_lineage.json`)**: Out-of-sample holdout evaluation compares multi-task loss, action accuracy, profit target error, and strategy selection accuracy between the active Champion and Challenger. Automatically archives superseded champions (`logs/models/archive/`), promotes qualifying challengers, logs evaluation history, and provides one-click rollback functionality.

  5. **Dynamic Dashboard Telemetry Integration (`reflex_dashboard/data/adapters.py`, `reflex_dashboard/components/neural_view.py`, `reflex_dashboard/state.py`)**: Replaced static fallback values in `get_neural_policy_data()` with real runtime calculations: live latent regime classification (`classify_market_regime`), real neural recommendations & action distributions (`LivePolicyController`), counterfactual regret & capture efficiency (`evaluate_counterfactual_regret`), and active champion version display (`MODEL: vX`).
- **Trade-offs**: Enforcing strict holdout outperformance on validation loss and action accuracy protects live trading from regressions, but requires sufficient labeled examples across multiple trading days before a challenger can earn promotion.

## ADR-19: Fail-Closed Emergency Liquidation, Ambiguous Order Submission Retention & Unified Dashboard Presentation Bundle (2026-11-03)
- **Context**: During emergency liquidation and panic recovery, network timeouts or incomplete broker responses could result in unverified order dispatches. If subsequent iterations treated unverified dispatches as failures and immediately resubmitted closing orders, duplicate closing orders or naked short positions could occur. Additionally, synchronous recovery execution inside strategy iteration loops coupled broker outages to trading cadence. On the dashboard side, fragmented snapshot processing across Reflex and Streamlit risked inconsistent telemetry freshness, flicker, and fabricated zero balances.
- **Decision**:
  1. **Durable Emergency Intent & Ambiguous Submission Retention (`dashboard/broker_client.py`, `strategies/position_ledger.py`)**: Persist emergency intent in SQLite before broker transmission. Any dispatch resulting in timeout or ambiguous broker response is marked as `unresolved`, blocking duplicate replacement orders until broker reconciliation confirms terminal status.
  2. **Worker Lease Exclusion (`strategies/position_ledger.py`, `strategies/recovery.py`, `strategies/recovery_worker.py`)**: Implemented recovery worker exclusion lease (`recovery_worker_heartbeat`) to ensure single-worker execution during broker emergency operations and decoupling recovery retry loops from strategy iteration cadence.
  3. **Unified Dashboard Presentation Bundle (`dashboard/presentation.py`, `reflex_dashboard/reflex_dashboard/data/adapters.py`, `dashboard/app.py`)**: Consolidated telemetry bundle generation into `build_dashboard_presentation_bundle`, ensuring consistent freshness indicators, resource generation tracking, and isolation between current totals and expired historical inventory without manufacturing zero balances or zero P&L.
- **Trade-offs**: Retaining unresolved emergency submissions prevents unsafe duplicate orders during broker outages, but requires explicit broker reconciliation before new closing submissions can proceed.
